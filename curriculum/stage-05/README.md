# S05 大模型定制开发

## 阶段定位

面向垂直领域完成模型微调、量化、部署和多智能体治理。目标不是只跑通训练脚本，而是证明定制模型值得使用，并能安全、稳定地进入应用链路。

## 前置知识

- 已通过 `S04-GATE`。
- 能构建 RAG/Agent、运行固定评估并分析 Trace。
- GPU 训练实验允许使用云算力；CPU 环境必须保留小样本演练路径。

## 课程列表

| 编号 | 主题 | 可观察目标 | 必做实验与完成证据 |
|---|---|---|---|
| S05-L01 | Hugging Face 与模型运行机制 | 使用 tokenizer、模型仓库和训练组件，读懂模型配置 | 加载并分析一个开放模型；提交架构、许可和资源模型卡 |
| S05-L02 | 数据构造、SFT 与全量微调 | 构建可审计训练集，理解监督微调和数据质量 | 训练小模型或小数据集基线；记录数据版本和评估结果 |
| S05-L03 | LoRA、P-Tuning 与 QLoRA | 比较参数高效微调方法的资源与效果 | 在同一任务上完成至少两种 PEFT 实验并给出取舍 |
| S05-L04 | 量化、并行训练与推理优化 | 解释量化误差、数据/模型并行及吞吐延迟权衡 | 比较量化前后质量、显存、首 token 延迟和吞吐 |

| S05-L07 | 权限、审计、监控与生产治理 | 实现最小权限、租户/用户上下文、成本和质量监控 | 生成审计记录；演练模型故障、工具故障和回滚 |

## 必做实验

- 比较“提示词/RAG 已足够”和“确实需要微调”的两个案例，说明何时不应微调。
- 对 SFT、LoRA/QLoRA 和量化模型运行同一冻结评估集。
- 模拟模型服务不可用，验证重试、备用模型、预设回复和告警。
- 构造 Agent 互相转交的循环，验证预算、超时和最大跳数能够终止执行。

## 主线项目增量

为知识库助手加入垂直领域定制模型、统一模型服务和多个职责清晰的 Agent；补齐权限、审计、成本监控、质量监控、降级与回滚。

## 闯关标准

`S05-GATE` 必须同时满足：

- 用冻结测试集证明定制模型相对基线的收益，并公开资源与质量代价。
- 模型服务可健康检查、限流、降级和回滚，不把训练实现泄漏给调用方。
- 多智能体间有明确输入输出协议、权限和终止条件。
- 完成独立挑战：为一个新垂直领域制作小型数据集、训练适配器、部署并接入主线应用。
