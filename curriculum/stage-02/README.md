# S02 大模型应用开发

## 阶段定位

把“能够调用模型”升级为“能够交付稳定应用”。重点是 Python 工程能力、数据处理、Web API、流式交互和结构化输出。

## 前置知识

- 已通过 `S01-GATE`。
- 能独立使用函数、模块、文件、异常和模型 API。

## 课程列表

| 编号 | 主题 | 可观察目标 | 必做实验与完成证据 |
|---|---|---|---|
| S02-L01 | 面向对象与 Python 工程结构 | 用类封装模型提供商、会话和配置，保持职责清晰 | 重构聊天客户端并保持 S01 行为兼容；提交类关系说明 |
| S02-L02 | 迭代器、生成器、装饰器与并发 | 使用生成器表达流式数据，用并发处理独立任务 | 实现可取消 token 流；验证取消后资源被释放 |
| S02-L03 | NumPy、Pandas 与实验数据 | 清洗实验结果，计算质量、耗时和用量统计 | 生成模型对比表与可复现分析脚本 |
| S02-L04 | MySQL 与持久化边界 | 设计会话和消息表，使用参数化查询并处理事务 | 保存/恢复多轮对话；验证失败事务不会留下半成品 |
| S02-L05 | Prompt Engineering 与 schema 校验 | 使用模板、少样本和输出解析器获得受约束结果 | 实现学习卡片 JSON schema；拒绝无效输出而不是直接渲染 |
| S02-L06 | FastAPI、SSE 与轻量前端 | 构建流式、可取消、有错误协议的聊天 API | 完成端到端聊天、停止生成和统一错误展示 |
| S02-L07 | Coze/Dify 原型与代码复刻 | 用低代码平台验证工作流，再识别平台边界 | 搭建原型并用 Python 复刻关键链路；提交差异清单 |

## 必做实验

- 对同步、线程和异步三种调用方式做延迟与取消行为对比。
- 向结构化输出注入缺字段、错类型和多余文本，验证服务端拒绝路径。
- 中断数据库写入，验证事务回滚和重复请求的幂等行为。

## 主线项目增量

将知识库助手升级为 FastAPI + 轻量前端应用，支持多轮流式聊天、停止生成、结构化学习卡片、会话持久化和清晰的错误状态。

## 闯关标准

`S02-GATE` 必须同时满足：

- 连续对话、停止生成、错误展示和 schema 校验的自动测试通过。
- 能解释浏览器、API、模型提供商和数据库之间的数据流与信任边界。
- 完成独立挑战：增加一种新的结构化学习产物，并证明无效结果不会进入界面或数据库。
- 提交一次 Coze/Dify 原型与 Python 实现的取舍复盘。
