# S01-L05 实验结果

实验日期：2026-09-21

## 实验环境

- 本地服务：Ollama 0.34.2
- 本地模型：`qwen3:4b`（Q4_K_M，约 2.5 GB）
- 云端模型：`qwen-plus`
- 本机处理器：Apple GPU

## 冷启动与热请求

两次请求固定使用相同模型、提示词、温度和 32-token 输出上限，只改变模型是否已经加载。

| 指标 | 冷启动 | 热请求 |
|---|---:|---:|
| `load_seconds` | 2.560 | 0.0038 |
| `total_seconds` | 4.299 | 1.481 |
| `output_tokens` | 32 | 32 |
| `tokens_per_second` | 20.90 | 22.69 |

结论：热请求的模型加载时间几乎归零，总等待时间减少约 2.82 秒；生成速度只小幅波动。第二次请求还命中了提示词缓存，因此总耗时变化不应全部归因于模型加载，但 `load_seconds` 提供了直接证据。

## 固定 JSON 任务对比

两端使用相同提示词，要求只输出一个包含 `term` 和 `definition` 的 JSON 对象；温度为 0，输出上限为 128 token。

| 指标 | 本地 `qwen3:4b` | 云端 `qwen-plus` |
|---|---:|---:|
| 请求是否返回 | 是 | 是 |
| 结束原因 | `length` | `stop` |
| 总耗时 | 8.51 秒 | 1.29 秒 |
| 输出 token | 128 | 30 |
| 可直接解析为 JSON | 否 | 是 |
| 满足字段要求 | 否 | 是 |

云端模型的合格输出：

```json
{"term": "Token", "definition": "大语言模型处理文本时的最小单位，可以是字、词或子词。"}
```

## 失败样本

- 现象：本地模型输出了任务分析过程，没有生成要求的 JSON，最终回答被截断。
- 证据：输出内容是分析文字；`done_reason` 为 `length`；`eval_count` 为 128，恰好达到上限；结果无法由 `json.loads()` 直接解析。
- 结论：在当前模型、Ollama 版本和请求配置下，`think=false` 没有可靠地阻止思考过程输出。本次本地结果不满足严格 JSON 任务要求；这不能推广为所有本地模型都不适合 JSON。

## 隐私边界

- Ollama 默认只看到应用发送的内容，不会自动读取本地文件。
- 本地请求发送到 `127.0.0.1`，数据通常不离开本机。
- 云端请求需要把消息发送给服务商，还需评估传输、日志保留、账号权限和合规要求。
- 本地推理能缩小数据外传边界，但仍需控制文件工具权限、本地日志和进程访问。

## 综合结论

本地模型适合数据不得离开设备或内网的任务，但应用不能只检查 HTTP 200；还要验证结束原因、响应结构和业务约束。提高严格输出可靠性时，应优先使用结构化输出或语法约束、模式校验、带变化的重试、更合适的本地模型，以及必要的人工复核。
