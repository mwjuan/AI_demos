# S01-L05 学习反思

## 为什么生成速度不用总耗时计算？

`eval_count` 是生成的 token 数量，`eval_duration` 是生成这些 token 的时间，因此二者相除反映生成阶段的速度。`total_duration` 还包含模型加载、提示词处理和其他开销，更适合衡量用户的实际等待时间。

## HTTP 200 是否代表任务成功？

HTTP 200 只能说明调用链路成功。应用还要检查生成是否完整，以及回答是否满足格式、长度和内容要求。链路成功、生成完成和业务合格是三个不同层次。

## 如何处理被截断的回答？

完全不改变条件的重试通常没有意义。普通聊天可以展示部分回答并明确提示截断；JSON、代码和自动化任务应判定为不合格。有效重试应改变输出上限、缩短任务、调整思考模式或继续生成。

## 为什么固定 JSON 更容易评测？

程序可以自动检查 JSON 能否解析、必需字段、字段类型、非空值和长度限制。结构正确不等于含义正确，因此语义质量仍需评分标准、人工检查或评测模型辅助。

## 本地模型是否能自动访问文件？

不能。模型只看到应用放进请求的内容。程序必须主动选择并读取文件，再把必要内容发送给模型；只有应用明确提供文件工具时，模型才可能间接访问文件。

## 隐私受限时如何提高可靠性？

提示词应给出明确、必要的任务约束，但不能只依赖模型自觉遵守。应用可以容忍代码围栏等常见包装，随后必须转换成统一结构并严格验证；还可以使用本地结构化输出或语法约束、温度 0、合理的输出上限、带变化的重试、更强的本地模型和人工复核。
