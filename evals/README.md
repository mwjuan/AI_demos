# 评估区

评估从 S01 开始记录，在不同阶段逐步升级；不再等到某个固定周次才引入。测试数据、基线和报告必须可版本化、可重复运行，并与开发时的示例分离。

## 分阶段评估

| 阶段 | 主要评估对象 | 最低证据 |
|---|---|---|
| S01 | 提示词、提供商、错误处理 | 单变量实验、响应/用量/耗时、失败记录 |
| S02 | API、流式交互、schema、持久化 | 单元与集成测试、取消/回滚/无效输出案例 |
| S03 | 分类、Embedding、训练过程 | 冻结数据集、模型指标、曲线、配置与基线 |
| S04 | 检索、引用、拒答、工具和 Agent | 至少 30 个固定案例、RAG/Agent 对比报告、Trace |
| S05 | 微调模型、推理服务、多智能体 | 冻结评估、资源成本、降级/回滚/权限演练 |
| S06 | CV、跨模态检索和生成 | 分类/检测/分割/检索指标、错误样本、安全检查 |

## S04 固定案例最低覆盖

- 笔记中可以回答的问题。
- 笔记中没有依据、应明确拒答的问题。
- 引用是否对应真实片段或图片区域。
- 冲突资料、过期资料和恶意提示注入。
- 工具选择、参数校验、权限拒绝和失败恢复。
- 延迟、输入 token、输出 token、费用和最大步骤。

## 评估纪律

- 开发集用于调试，冻结测试集只用于比较最终方案。
- 报告必须同时给出质量、耗时、资源/费用和失败样本，不能只展示平均分。
- 每次实验记录数据版本、模型、参数、代码版本和运行环境。
- 改动未优于基线时保留结论，不为“看起来提升”而更换测试集。
- 测试数据在对应能力实现前保持最小化，避免为了格式提前决定尚未学习的设计。
