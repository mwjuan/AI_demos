# 当前教学模式

2026-10-21，学习者明确要求调整教学：代码由助手生成，不再手写 Python 练习，直接学习大模型开发相关的流程和设计。

## 分工与节奏

- 学习者负责理解需求、解释数据流、选择方案、判断取舍和验收结果。
- 助手负责生成实现、运行实验、排错、验证和保存证据；需要实现时直接提供可运行结果，不再给 TODO 骨架让学习者逐行补代码。
- 每次围绕一个实际场景：明确需求和成功条件 → 画请求或数据流程 → 讨论关键设计与失败路径 → 助手实现或演示 → 学习者判断结果。
- Python、框架和工具用法按理解设计所需补充，不以语法、手写类或抄写实现作为学习主线。
- 验收看“能设计、能解释、能验收”。代码能运行与必要测试仍由助手保证；模拟验证不能声称为真实模型验证。
- 设计练习让学习者做选择并解释原因，不要求手写代码。不因教学模式改变而自动标记课程或阶段通过。

## 本轮设计练习

场景：用户问题已经进入历史，模型请求超时，用户点击“重试”。

学习者已回答：复用原问题，因为历史越长请求用量越大，应尽可能减少历史。复用选择正确，理由体现了用量意识；助手补充：重试属于同一个问题的另一次请求尝试，重复追加会扭曲对话语义，用量增加是附带影响。不能由此推导出历史越少越好；保存的历史与本次发送的上下文需要分开设计。

上下文讨论已进行：学习者回答提供两个学习方案；助手补充仍然有效的原始要求，并讲解全部历史、最近几轮、约束/摘要加最近几轮三种方式。学习者随后复述：“上下文组装，长期约束单独保存，加最近几轮的对话。”基本思路理解已确认；相关旧信息的补充与约束更新仍可在后续场景深化，未将完整上下文管理能力或整课标为通过。

当前概念预览为工作流与 Agent 的区别：固定工作流由程序规定下一步选择规则，可以包含模型、条件分支、循环和工具；Agent 在约定权限及停止条件内，由模型根据执行结果选择后续行动。此处只用于应用架构判断，不提前进入 S04 实现或标记阶段通过。卡片任务继续以可校验、可恢复的固定工作流作为当前设计。

Agent 概念讨论进展：对“用户只给学习目标，系统自己找资料并安排内容”的场景，学习者回答需交给模型判断“寻找资料，安排学习内容”。该回答识别了两项职责；助手进一步拆解检索问题与关键词、资料是否有依据且足够、知识先后顺序与时间约束等决策。

当前讲解工具调用的概念循环：模型提出工具名及参数 → 应用校验并执行真实工具 → 将工具结果作为数据返回 → 模型根据证据选择继续查找或组织答案。模型提出调用不等于工具已执行；应用负责工具范围、参数检查、运行次数与停止条件。仅概念讲解，未连接搜索工具或执行实际检索，不视为 S04 工具实现完成。
